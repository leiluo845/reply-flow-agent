# ReplyFlow 产品契约 v1.0

> 本文件是阶段 1 的范围冻结文档。它把 PRD 中已经确认的产品定位、角色、处理级别、演示方式和取消项转成后续开发必须遵守的执行契约。若本文与后续实现冲突，以本文和 PRD v2.1 为准；若要改变本文内容，必须由用户明确确认。

## 1. 项目性质

ReplyFlow 是个人独立研究型作品，用于展示产品经理对 AI Agent 嵌入 B 端业务流程的理解。项目中的品牌、店铺、店管、买家、邮件、订单、物流、回复依据、评测数据和发送结果全部为虚构数据。

本项目不代表任何实习公司的真实系统、真实数据、真实接口、真实建设计划或真实经营结果。

## 2. 产品定位

ReplyFlow 不是独立聊天机器人，也不是一套新的客服系统。它是嵌入电商邮件系统“顶部聚合站内信”的 AI 回复能力层。

产品工作对象是“聚合后的买家站内信会话”，不是原始邮箱里的单封邮件。原始邮箱、亚马逊邮件和收件箱只作为邮件来源与原件查看区，完整 AI 回复能力只出现在顶部聚合站内信中。

标准流程如下：

```text
演示控制台输入邮件
  -> 写入本地原始收件箱
  -> 识别为买家站内信
  -> 创建顶部聚合会话
  -> 单 Agent 分析
  -> 调用本地工具查询事实
  -> 检索只读回复依据
  -> 风险网关分级
  -> 生成草稿或模拟发送
  -> 写入本地 outbox、Trace 和 Audit
```

## 3. 唯一业务角色

系统只有一个业务角色：店管。

店管负责查看聚合站内信、触发 AI 回复、编辑草稿、核对高风险内容和完成本地模拟发送。产品负责人、作品演示者、AI 编程助手属于项目协作身份，不是系统业务角色。

第一版不实现登录、角色切换、组织权限、多人协作和后台管理。

## 4. 三级 AI 处理

页面展示“AI 处理级别”，后台保留 R0-R3 风险等级。处理级别说明店管如何操作，风险等级说明系统如何控制。

| AI 处理级别 | 页面含义 | 允许场景 | 页面动作 | 写入条件 |
|---|---|---|---|---|
| 一级·自动处理 | 系统可在本地模拟自动回复 | 白名单低风险、事实完整、无金额/责任/确定时限承诺 | 不展示人工按钮，显示“AI已回复” | 风险网关通过，系统生成确认标记，写入本地 outbox |
| 二级·人工确认 | AI 可生成草稿，但必须店管确认 | 尺码、换货、缺少信息、一般退换咨询、依据不足但非高风险 | 店管点击“AI回复”，草稿进入输入框 | 店管编辑或确认后点击模拟发送 |
| 三级·高风险核对 | AI 只提供参考回复，必须店管逐项核对 | 退款、赔偿、拒付、投诉、法律威胁、事实冲突、工具失败、低置信度、模型草稿含承诺 | 店管点击“生成参考回复”，页面显示风险原因和核对清单 | 核对清单全选并二次确认后，才能写入本地 outbox |

一级只能作为演示中的本地模拟自动回复，不证明真实 Amazon 店铺可以自动发送。

## 5. 风险等级

| 风险等级 | 判定 | 对应控制 |
|---|---|---|
| R0 | 事实完整，命中低风险白名单，没有高风险表达 | 可进入一级或二级 |
| R1 | 缺少订单号、图片、尺码、客户信息等，但可以通过澄清继续 | 二级，生成澄清或确认草稿 |
| R2 | 涉及退款、赔偿、拒付、投诉、法律威胁、事实冲突、工具失败、低置信度或可能形成承诺 | 三级，强制店管核对 |
| R3 | 真实发送、真实退款、修改订单、泄露密钥、绕过确认等架构禁止行为 | 直接阻断，不提供页面路径 |

模型输出不能降低本地风险网关的判定。草稿生成后必须再次扫描，若草稿引入退款、赔偿、金额、责任或确定时限承诺，立即升级为三级。

## 6. 模拟邮件浮窗

模拟邮件浮窗是作品演示入口，不是正式业务菜单。页面右下角固定“模拟收到邮件”浮动按钮，点击后打开模态浮窗，提交成功后关闭。

浮窗字段：

| 字段 | 要求 |
|---|---|
| 邮件正文 | 必填，支持一行或多行英文 |
| 邮件主题 | 可选，空值时生成虚构主题 |
| 模拟发件人 | 可选，空值时生成 `buyer-xxx@example.com` |
| 关联模拟订单 | 可选，只作为同步上下文，不作为答案标签；候选展示订单号、商品、金额和履约状态，选中后即时展示订单摘要 |
| 运行模式 | 侧栏选择 Demo Mode 或 Interactive Mode |
| 接收后自动运行 Agent | 浮窗内可选，默认勾选 |

浮窗按钮：

| 按钮 | 行为 |
|---|---|
| 模拟收到邮件 | 校验正文，写入本地收件箱，创建聚合会话，并按勾选项运行 Agent |
| 仅接收不处理 | 只写入和聚合，状态停在待分析 |
| 清空输入 | 清除当前输入，不影响数据库 |
| 重置演示数据 | 二次确认后重置本地演示数据 |

点击“模拟收到邮件”后，页面必须展示真实状态变化：原始收件箱计数增加、顶部聚合站内信待处理计数增加、新会话置顶并自动选中、右侧 Trace 出现状态和工具调用。

## 7. 工具与事实边界

Agent 不能凭模型记忆编造订单、物流、退款或平台规则。订单和物流事实必须来自本地工具，回复依据必须来自项目内置的只读虚构资料。

第一版固定 8 个 MCP Tools：

| Tool | 权限 | 作用 |
|---|---|---|
| `ingest_simulated_email` | 模拟写入 | 写入虚构邮件和同步元数据 |
| `get_email` | 只读 | 读取原始邮件 |
| `find_order` | 只读 | 查询虚构订单 |
| `get_shipping_status` | 只读 | 查询虚构物流轨迹 |
| `search_reply_basis` | 只读 | 检索只读回复依据 |
| `get_reply_tone` | 只读 | 获取英文回复语气和禁用表达 |
| `save_reply_draft` | 模拟写入 | 保存 AI 草稿和店管编辑稿 |
| `send_simulated_reply` | 模拟写入 | 确认后写入本地 outbox |

`save_reply_draft` 和 `send_simulated_reply` 必须带 `operation_id`。重复提交同一 `operation_id` 且内容一致时返回历史结果，不重复写入；同一 `operation_id` 内容不同必须阻断。

## 8. Coze 与自建控制层分工

Coze 负责概率型 AI 能力，例如自由文本意图识别、实体抽取和英文草稿生成。Python 自建控制层负责确定性业务能力，例如邮件接入、聚合会话、工具调用、风险网关、状态机、确认、幂等、审计和本地模拟发送。

完全依赖 Coze 不适合本项目，因为页面状态、写入边界、幂等和高风险拦截需要可测试、可复现的本地业务控制。完全自研也不适合第一版，因为模型编排、Prompt 调试和自由文本生成会占用过多成本。混合方案更适合作品集展示：既能体现 AI Agent 能力，也能体现产品经理对业务边界和风险控制的理解。

## 9. 运行模式

| 模式 | 能力 | 限制 |
|---|---|---|
| Demo Mode | 无模型凭证可运行；覆盖预置案例和有限规则；真实调用本地工具、风险网关和 SQLite | 超出规则范围的自由文本必须提示能力限制，不能伪装成模型理解 |
| Interactive Mode | 调用 Coze Workflow 处理自由文本分析和草稿 | Coze 不得执行发送、退款、改订单或覆盖本地风险结果 |

任何模式下，所有发送都只写入本地 outbox，不连接真实 Amazon、邮箱、支付或订单系统。

## 10. 取消项

下列内容已经被明确取消。后续 AI 或开发者不得因为“看起来更完整”而自行恢复。

| 取消项 | 禁止实现 |
|---|---|
| 客服主管和多角色 | 主管审核、管理员、审批队列、角色切换、权限矩阵 |
| 政策邮件产品 | 政策文件夹、亚马逊官方政策邮件分类、政策抽取、政策版本管理、政策发布、政策治理 |
| 工单化客服 | 工单列表、工单状态、`create_support_ticket` |
| 退款审核 | 退款审核队列、退款金额审批、`create_refund_review_request` |
| 真实外部写操作 | 真实邮件发送、真实退款、修改订单、修改地址、取消订单 |
| 复杂架构扩展 | Multi-Agent、LangGraph、FastAPI、独立前端框架、Docker |

允许保留项目内部虚构回复依据文件，但它只用于只读检索，不提供上传、管理、发布和治理页面。

## 11. 每阶段开工前检查

每个后续阶段开始前，AI 必须先确认：

1. 本轮是否仍发生在“顶部聚合站内信”内，而不是独立聊天页面；
2. 是否仍只有店管一个业务角色；
3. 是否没有改变一级、二级、三级定义；
4. 是否没有让模型绕过工具、风险网关或店管确认；
5. 是否没有新增取消项；
6. 是否没有引入真实外部写操作；
7. 是否有对应测试或人工验收方式；
8. 是否会更新 `PROJECT_STATUS.md` 并提交 Git。

## 12. 阶段 1 验收标准

阶段 1 完成后，新 AI 只读取以下四份文档，就应能复述正确产品模型，并知道后续哪些功能不能做：

1. `docs/product_contract.md`
2. `docs/scenario_catalog.md`
3. `docs/state_catalog.md`
4. `docs/decision_log.md`

若复述出现客服主管、工单、退款审核、政策治理、真实发送或 Multi-Agent，本阶段视为未通过。
