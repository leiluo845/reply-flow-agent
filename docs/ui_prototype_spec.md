# ReplyFlow 页面规范：原邮件工作台内置 Agent

## 1. 页面定位

ReplyFlow 不是新建的客服系统，而是嵌入现有“亚马逊客服邮件能力建设”原型中的 Agent 能力层。页面骨架、信息密度和视觉分区必须优先复刻原型；Agent 只出现在邮件回复工作区及模拟邮件入口。

本页面用于个人作品演示，所有店铺、邮件、订单、物流和回复均为虚构数据。除模拟邮件和回复发送外，不连接真实 Amazon、邮箱或订单接口。

## 2. 页面骨架

从左到右固定为：

1. 深蓝色 OMS 导航栏：展示七星 OMS、业务菜单和当前“客服邮件”高亮；菜单只做展示，不可点击。
2. 顶部白色标题栏：展示“邮件消息”、语言、通知、全屏、主题和用户信息；图标只做展示。
3. 邮件工具栏：店铺、未读、状态、发件人、搜索、日期、附件、更多筛选、搜索、重置；全部只做占位，不实现筛选。
4. 邮件列表工具栏：同步时间、收件时间、排序、已读/未读、无需回复、已在平台回复；全部只做占位。
5. 左侧邮箱树：展示邮箱、收件箱、发件箱、站内信和亚马逊邮件；只做展示，不支持切换文件夹。
6. 中间会话列表：阶段 A 使用原 HTML 的 6 条静态会话，允许点击会话切换详情；阶段 B 再增加 AI 风险标签和模拟邮件置顶逻辑。
7. 中间邮件详情：展示买家邮件气泡、订单号、附件占位、客服回复气泡和底部回复输入框；只有回复输入框、AI 操作和模拟邮件入口可交互。
8. 右侧订单信息：展示订单号、Shipped/FBM 标签、订单状态、履约方式、仓库、物流公司、跟踪号、金额和商品信息；只读展示。

页面默认展示一封虚构买家邮件和一条虚构订单，保证打开页面即可看到完整工作台。

## 3. 智能客服开关（阶段 B）

阶段 A 不显示智能客服开关，也不调用 Coze。以下内容只适用于阶段 B。

- 位置：邮件详情区顶部，靠近会话状态。
- 默认：关闭。
- 关闭：模拟邮件仍可进入收件箱和会话列表，但不调用 Coze，不生成或发送 AI 回复。
- 开启：模拟邮件提交后自动调用 Coze Analyze/Draft；当前会话若处于待分析状态，也可以立即处理。
- 页面只调用 Coze Workflow，不再展示 Demo Mode / Interactive Mode 切换。
- Coze 调用失败：会话进入失败状态，页面显示“AI 处理失败”和错误码，不切换本地规则，不伪造草稿。
- AI 处理失败时显示 `重试 AI` 按钮；智能客服关闭时按钮禁用，开启后重新调用同一 Coze Workflow。
- 这是全局开关，不是当前邮件开关。开启前提示当前待处理数量；确认后批量处理所有 `WAITING_ANALYSIS` / `FAILED` 的买家站内信。
- 批处理期间展示进度条、当前序号和 L1/L2/L3/失败计数；关闭开关后允许当前邮件完成，但不再启动排队中的邮件。
- 新站内信接入时，如果开关仍开启，则自动加入队列；已回复、待确认、高风险核对中的邮件不得重复处理。

## 4. 风险等级与回复行为（阶段 B）

后台继续使用既有 `R0-R3` 风险等级和 `L1-L3` 处理级别，页面不简化为两档：

| 处理级别 | 页面标识 | 回复行为 |
|---|---|---|
| L1 | `L1 · 低风险 · AI回复` | Coze 生成草稿后，通过本地风险网关，自动写入本地模拟发件箱；邮件列表和回复气泡显示风险等级与 AI 标识 |
| L2 | `L2 · 中风险 · AI生成` | 草稿填入回复输入框，店管可编辑；不自动发送，点击回复区按钮后写入本地模拟发件箱 |
| L3 | `L3 · 高风险 · AI生成，需核对` | 草稿填入回复输入框并高亮风险；显示高风险核对清单，未完成清单时发送按钮禁用，完成后才可模拟发送 |

所有“发送”只写入本地 SQLite `outbox`，不会发送真实邮件。

## 5. 批次撤回（阶段 B 演示能力）

- 入口是一次性按钮 `撤回上一轮处理（演示）`，不是持续状态开关。
- 只允许撤回最近一个已完成批次；批次处理中按钮禁用，避免中途回滚。
- L1 的本地模拟发件箱记录、L2/L3 的本地草稿和风险状态回退到待处理状态。
- 撤回只改变本地演示状态，不撤回真实 Amazon 邮件；数据库保留 `stage_b_rollback_events` 记录。
- 撤回不影响其他批次，也不影响撤回后新进入的邮件。

## 6. 模拟邮件台（阶段 B）

- 入口：页面底部固定浮动按钮 `模拟邮件台`。
- 点击后：打开模态浮窗，不改变主页面骨架。
- 浮窗字段：主题、正文、模拟发件人、模拟邮箱、关联订单。
- 订单候选：展示订单号、商品名、金额和履约状态；选中后展示订单摘要。
- 点击 `模拟收到邮件`：写入本地原始收件箱，创建顶部聚合会话，新会话置顶并自动选中；若智能客服开关已开，则立即调用 Coze。
- 智能客服开关关闭时：只完成接收和聚合，不调用 AI。
- 重复点击同一邮件：由 `source_message_id` 和 `operation_id` 保证不重复写入。

## 7. 交互边界

### 阶段 A

只允许以下交互：

- 点击会话列表切换邮件详情；
- 会话切换后更新右侧订单匹配/未匹配展示；
- 回复输入框输入、编辑和清空；
- 邮件列表、邮件详情和订单区域原生滚动。

原型中的导航、筛选、文件夹、排序、搜索、分页、订单操作、时间切换、提醒、同步和工具图标均为静态展示。保存草稿、发送、新建邮件和弹窗只保留外观，阶段 A 不执行逻辑。

### 阶段 B

在阶段 A 的 HTML 基线上增量加入智能客服开关、模拟邮件台、L2/L3 AI 草稿、风险核对和模拟发送，不重新设计页面骨架。

## 8. 实现约束

- 阶段 A 以原始单文件 HTML 作为主展示页面，不依赖 Streamlit 重建 DOM。
- 阶段 A 不调用 Coze、SQLite Agent 流程或真实外部接口；数据来自原 HTML 的静态演示内容。
- 阶段 B 复用现有 Python 状态流转、Coze、SQLite、风险网关和审计能力，通过增量 JavaScript 接入原页面。
- 阶段 B 的动态模拟邮件写入本地 SQLite，服务重启后仍可恢复；Coze PAT 只从 `.env` 读取。
- 不新增 FastAPI、前端框架、真实 Amazon 接口或第二套业务系统。

## 9. 验收标准

### 阶段 A

- [ ] 页面打开即呈现原 HTML 风格的 OMS 邮件工作台，而不是独立聊天页面。
- [ ] 页面默认没有智能客服开关、AI 标签、风险标签或模拟邮件台。
- [ ] 只有会话切换、订单联动、回复输入和滚动产生交互变化。
- [ ] 其他区域不可改变业务状态或跳转外部页面。

### 阶段 B

- [ ] 除 Agent 开关、模拟邮件台和回复操作外，其他区域不可点击或只作占位。
- [ ] 智能客服关闭时，模拟邮件不会调用 Coze。
- [ ] 智能客服开启时，L1 自动回复，L2 草稿待确认，L3 草稿高风险核对。
- [ ] 每条回复旁显示处理级别和 AI 回复标识。
- [ ] Coze 失败时显示失败提示，不回退 Demo Mode。
- [ ] Coze 失败时显示“重试 AI”；重试复用原邮件和订单上下文，不重复创建邮件。
- [ ] 模拟邮件可关联订单，订单摘要和右侧订单栏同步更新。
- [ ] 发送只写入本地模拟发件箱，重复点击不重复发送。
- [ ] 全局开关开启前提示待处理数量，确认后批量处理并展示进度。
- [ ] 开关开启期间接入的新邮件自动入队；关闭后不启动排队中的新邮件。
- [ ] 批次完成后可撤回上一轮演示处理，处理中的批次不可撤回，且保留回退审计记录。
