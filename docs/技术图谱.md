# ReplyFlow Agent 技术图谱

## 1. 一句话概括

ReplyFlow 不是“一个调用大模型的聊天框”，而是一个嵌入电商邮件系统顶部聚合站内信的单 Agent 回复能力：

> Coze 负责理解和生成，本地控制层负责查事实、判风险、管状态、控发送。

项目全部使用虚构数据和本地模拟发送，不连接真实 Amazon、邮箱、支付或订单写入接口。

## 3. 一封邮件的完整处理链路

```text
输入一行模拟邮件
  ↓
写入 SQLite 原始收件箱
  ↓
识别是否为买家站内信
  ↓
创建顶部聚合会话
  ↓
Coze Analyze：识别意图、提取显式订单号、返回置信度
  ↓
本地 MCP Tools：查询订单、物流、回复依据和语气
  ↓
本地风险网关第一次判断
  ↓
Coze Draft：仅接收已验证事实和风险上下文
  ↓
本地风险网关二次扫描草稿
  ↓
根据最终结果执行 L1 / L2 / L3
  ↓
写入本地 outbox、Tool Trace、Task Run 和 Audit
```

## 4. 技术栈分层

| 层级 | 技术/模块 | 作用 |
|---|---|---|
| 页面 | HTML、CSS、JavaScript、本地 Python HTTP 服务 | 复刻原邮件工作台并增量接入 Agent |
| 模型编排 | Coze Workflow | Analyze 和 Draft 两个概率型模型步骤 |
| Agent 编排 | `InteractiveOrchestrator` | 串联模型、Tools、风险、状态和重试 |
| 工具协议 | MCP Python SDK | 统一暴露本地事实查询和模拟写入能力 |
| 能力规范 | 3 个 Markdown Skills | 规定触发条件、步骤、工具、禁止事项和升级条件 |
| 业务数据 | SQLite、JSON 种子数据 | 保存虚构邮件、订单、物流和处理结果 |
| 数据访问 | Repository 层、Pydantic | 约束 Schema，隔离 SQL 和业务编排 |
| 控制逻辑 | Python 风险网关、状态机 | 确定性判定风险、状态和可执行动作 |
| 测试 | pytest | 单元测试、控制测试、端到端测试和评测测试 |
| 观测 | Trace、Audit、Task Run | 记录每次工具调用、状态变化和操作结果 |
| 评测 | JSONL 案例、Markdown/JSON 报告 | 验证准确性、安全边界和 No-Go 条件 |

## 5. Coze 模型编排层

Coze 只负责概率型能力，不拥有最终业务控制权。

### Analyze

输入：

- 邮件主题
- 邮件正文
- 可选订单上下文

输出：

- `is_buyer_message`
- `intent`
- `order_id`
- `missing_fields`
- `confidence`

本地会再次校验输出 Schema 和意图枚举。未知意图不会直接进入风险路由。

### Draft

输入：

- 原始邮件
- 已验证订单/物流事实
- 只读回复依据
- 回复语气
- 初步风险上下文

输出：

- 回复主题
- 英文回复正文

Coze 不允许执行：

- 真实发送邮件
- 真实退款或赔偿
- 修改订单或地址
- 覆盖本地风险结论
- 绕过人工确认

## 6. Skills 层

Skills 是 Agent 的能力说明和行为约束，不是简单的函数封装。

### `email_triage`

- 读取原始邮件
- 只提取邮件中明确出现的订单号
- 调用 `find_order` 验证订单
- 输出意图、订单号、缺失字段和置信度
- 禁止猜测订单、编造事实或直接发送

### `reply_drafting`

- 使用已验证事实和只读回复依据生成草稿
- 遵循英文客服语气
- 不补充未经验证的订单、物流、退款或平台规则
- 发现承诺风险时交给风险网关升级

### `risk_routing`

- 根据邮件、分析结果、Tool 结果和草稿选择 R0-R3
- 将风险映射到 L1-L3 或 BLOCKED
- 生成 L3 核对清单
- 不允许模型自行降低风险等级

## 7. MCP Tools 层

当前固定 8 个 Tool：

| Tool | 类型 | 作用 |
|---|---|---|
| `ingest_simulated_email` | 模拟写入 | 写入虚构邮件并创建聚合上下文 |
| `get_email` | 只读 | 读取原始邮件 |
| `find_order` | 只读 | 查询并验证订单 |
| `get_shipping_status` | 只读 | 查询物流轨迹 |
| `search_reply_basis` | 只读 | 检索项目内置回复依据 |
| `get_reply_tone` | 只读 | 获取回复语气与禁用表达 |
| `save_reply_draft` | 模拟写入 | 保存 Agent 草稿和店管编辑稿 |
| `send_simulated_reply` | 模拟写入 | 确认后写入本地 outbox |

所有 Tool 都返回结构化结果、错误码和 `trace_id`。写入类 Tool 必须带 `operation_id`；重复请求不会重复写入，内容冲突会被阻断。L3 发送还必须提交完整核对清单。

## 8. 风险网关与处理级别

### 风险等级 R0-R3

| 等级 | 含义 | 典型控制 |
|---|---|---|
| R0 | 事实完整，低风险 | 可进入 L1 或 L2 |
| R1 | 信息不完整但可澄清 | 进入 L2 |
| R2 | 退款、拒付、投诉、法律威胁、事实冲突、Tool 失败或低置信度 | 进入 L3 |
| R3 | 真实发送、退款、修改订单等架构禁止动作 | 直接阻断 |

### 处理级别 L1-L3

| 级别 | 页面行为 | 发送条件 |
|---|---|---|
| L1 | 低风险自动处理 | 风险网关通过后写入本地模拟 outbox |
| L2 | 生成草稿并填入原回复框 | 店管确认或编辑后模拟发送 |
| L3 | 生成草稿并显示高风险提示 | 店管完成核对清单后模拟发送 |

R0-R3 描述风险，L1-L3 描述页面处理方式，两者不是同一维度。

风险网关会扫描：

- 退款或赔偿承诺
- 金额承诺
- 确定送达时间承诺
- 责任或法律结论
- 未验证订单/物流事实
- 订单身份冲突
- Tool 失败或回复依据冲突
- 提示注入文本

## 9. 状态机

核心状态：

```text
WAITING_ANALYSIS
  → AI_ANALYZING
  → COLLECTING_FACTS / WAITING_USER_INFO
  → RETRIEVING_REPLY_BASIS
  → DRAFTING
  → RISK_CHECKING
  → AUTO_REPLYING
  → SIMULATED_SENT
  → COMPLETED
```

需要人工协同时进入：

```text
DRAFT_SAVED
  → WAITING_USER_CONFIRMATION   # L2
  → WAITING_HIGH_RISK_CHECK     # L3
```

Coze 失败进入 `FAILED`，页面提供「重试 AI」。重试复用原始 `source_message_id`，不会重复创建邮件；已完成会话再次提交则由幂等机制返回历史结果。

## 10. 数据与证据

SQLite 保存：

- `emails`：原始模拟邮件
- `aggregate_threads`：顶部聚合会话
- `orders`、`shipping_events`：虚构订单和物流
- `reply_drafts`：AI 草稿与店管编辑稿
- `task_runs`：任务状态
- `risk_decisions`：风险等级和核对清单
- `tool_traces`：Tool 调用记录
- `audit_logs`：状态变化和操作记录
- `outbox`：本地模拟发件箱
- `idempotency_keys`：重复请求控制

数据读取原则：订单、物流和回复依据必须来自本地 Tool；模型不能凭记忆补全。

## 11. 评测与 ROI

### 离线评测

当前评测包含 30 条案例，其中 13 条为 R2 高风险案例，关注：

- 意图识别
- 订单号识别
- Tool 选择
- L1/L2/L3 处理级别
- 风险识别
- 动态接入
- 任务完成
- 未授权承诺违规
- 无依据订单事实违规

当前实际结果：

- 动态接入率：100%（29/29）
- Demo 未授权承诺违规：0
- Interactive 未授权承诺违规：1
- 无依据订单事实违规：0（Demo / Interactive）
- Demo 高风险召回：61.5%
- Demo 结论：No-Go
- Interactive 复测（2026-09-03）额度可用但模型安全指标未达标：高风险召回 61.5%（8/13），并有 1 条未授权承诺、4 条结构校验失败，因此 No-Go

No-Go 是诚实的评测结论：当前版本不应扩大自动化范围，需要继续修复高风险识别和复杂语义覆盖。

### ROI 敏感性分析

页面支持编辑：

- 月邮件量
- L1/L2/L3 占比
- 原人工处理时间
- AI 后处理时间
- 人工小时成本
- 单次模型成本
- 月维护成本
- 错误概率
- 单次预期损失

输出人工节省、成本、风险成本、净收益和盈亏平衡量。所有结果都是虚构的参数化敏感性分析，不是实际业务 ROI 或上线承诺。

## 12. 这个技术图谱体现的能力

这个项目重点展示的不是“堆了多少框架”，而是：

1. 能把 Agent 放入已有 B 端业务流程，而不是另做一个聊天页面；
2. 能拆分模型能力与确定性业务控制；
3. 能设计 Skills、Tools、状态机和人机协同边界；
4. 能把高风险场景从自动发送路径中隔离出来；
5. 能用 Trace、审计、幂等和评测证明系统行为；
6. 能诚实展示 No-Go 和模型调用失败，而不是只展示成功截图；
7. 能用 ROI 敏感性分析讨论假设，而不虚构真实收益。
