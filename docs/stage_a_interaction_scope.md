# 阶段 A 页面交互范围

## 目标

阶段 A 只建立原亚马逊客服邮件工作台的可核对基线，不接入 Coze、风险网关、SQLite Agent 流程或智能客服控件。页面应保持原 HTML 的结构、文案、密度和 6 条静态会话。

## 保留交互

1. 点击会话列表中的邮件，切换选中会话。
2. 切换会话后更新邮件详情和右侧订单匹配/未匹配展示。
3. 回复输入框可聚焦、输入、编辑和清空。
4. 邮件列表、邮件详情和订单区域保留原生滚动。

## 静态展示

以下元素保留外观，但阶段 A 不实现业务行为：

- OMS 导航、客服邮件子菜单和顶部工具图标。
- 店铺、未读、状态、发件人、关键词、日期、附件和更多筛选。
- 搜索、重置、文件夹、邮箱树、全选、排序和分页。
- 已读/未读、无需回复、已在平台回复、删除、翻译、标签和上传附件。
- 保存草稿、发送、新建邮件、订单操作、退款、订单外链和所有相关弹窗。
- 北京时间/站点时间、提醒、同步等不属于 Agent 展示的控件；不新增原型中没有的元素。

## 数据边界

- 页面使用原 HTML 中的 6 条静态站内信和原型订单信息。
- 不加载后端 30 封 Agent 测试邮件，不调用 Coze，不写入真实或本地业务状态。
- 阶段 B 再在相同会话结构上增加智能客服开关、风险标签、AI 草稿和发送逻辑。

## 验收标准

- 打开页面即为 AI 未接入的原客服邮件工作台。
- 只有会话切换、订单联动、回复输入和滚动会产生交互变化。
- 点击其他按钮、筛选、文件夹、订单操作或外链不会改变业务状态或跳转。
- 页面可直接打开，且可通过本地静态服务器访问。
