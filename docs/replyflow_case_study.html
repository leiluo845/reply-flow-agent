ReplyFlow｜高风险售后 Agent
评测与人机协同工作台

一个搭载在电商邮件系统顶部聚合站内信上的 AI 回复能力原型：让低风险邮件更快处理，让中风险邮件可编辑确认，让高风险邮件在发送前被明确拦截。

演示边界：邮件、订单、物流、发送和 ROI 均为虚构或本地模拟；不连接真实 Amazon、邮箱、支付或订单写入接口。Coze 只负责 Analyze/Draft，本地控制层负责事实、风险、状态、确认、幂等和审计。

01｜为什么做

原页面增量接入保留店管熟悉的邮件工作台，不另造聊天产品。
三级处理L1 自动发送 · L2 草稿确认 · L3 草稿+高风险核对。
可评测、可回放每次任务都有风险决策、Tool Trace、审计和幂等标识。

04｜风险分级与人机协同

处理级别典型场景系统动作人工边界
L1 / R0–R1有订单依据的物流状态咨询通过风险网关后写入本地模拟发件箱无需逐封确认，但仍保留 Trace
L2 / R1尺码、换货等需要措辞判断的咨询生成草稿并填入原回复框店管编辑/确认后才可模拟发送
L3 / R2退款、拒付、投诉或高承诺风险生成草稿并显示风险原因核对清单未完成时发送被阻断

06｜项目取舍与限制

选择理由
Coze + 自建控制层用 Coze 快速验证模型编排，用本地代码掌控事实、风险、状态和审计；两者职责可测试、可替换。
虚构数据 + 本地 outbox独立演示、不泄露公司数据，也不把作品误包装成已上线系统。
不做多 Agent/真实写接口聚焦单 Agent 客服回复和高风险人机协同，控制演示范围与安全边界。
ROI 只做敏感性分析帮助讨论假设区间，不声称真实财务收益。
